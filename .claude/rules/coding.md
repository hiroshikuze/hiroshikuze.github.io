# rules/coding.md — コーディング規約

すべてYes/Noで判定できる条件として記述。Noの場合は修正してから進む。

---

## 変更前チェック

- [ ] 編集するファイルを事前にReadツールで読んだか？
- [ ] 変更範囲は依頼された内容のみか（依頼されていないリファクター・コメント追加を含んでいないか）？
- [ ] 新しいファイルを作成する前に、既存ファイルへの追記で対応できないか確認したか？

## 外部通信の実装前チェック

新しい `fetch`（AI API・Stripe・Turnstile・CDN・自社バックエンドAPI等、外部への通信が発生する箇所すべて）を追加・変更する際に適用する。

- [ ] リトライが実装可能か検討したか？（不可能・不要と判断した場合もその理由をコードコメントまたはdecision-logに残したか）
- [ ] リトライする場合、対象は「ネットワークエラー・5xx・429のみ」で「4xx（429を除く）」は対象外にしているか？（サーバーの明確な拒否応答を再送しない）

## コード品質

- [ ] OWASP Top 10（XSS・SQLインジェクション・コマンドインジェクション等）を導入していないか？
- [ ] 使われなくなったコードを残していないか？（後方互換シムを作らず削除する）

## Phase 1 固有（HTML / vanilla JS）

- [ ] ユーザー入力をDOMに挿入する際、`innerHTML` に直接代入していないか（`escapeHTML` を通しているか）？
- [ ] APIキーはコードにハードコードされておらず、UIのinputから取得しているか？
- [ ] `fetch` を含む非同期処理はすべて `try/catch` で囲まれているか？

## Phase 2 固有

- [ ] import順序は「外部ライブラリ → 内部モジュール → 型定義」の順か？
- [ ] `any` 型を使っていないか？（やむを得ない場合はインラインコメントで理由を明記）
